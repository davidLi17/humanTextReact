# 26.10.19

## What's changed

- 网页元素截图和弹窗图片草稿改用扩展自身 IndexedDB 保存 Blob，会话只保存图片引用。打开历史时按需读取预览，发送和追问时还原模型需要的图片数据。
- 旧版 Base64 会话和图片草稿自动迁移；先保存 Blob，再一起写入会话和草稿引用。单会话 JSON 和全量备份继续包含完整图片，可导入其他安装。
- 删除会话、编辑或重试截断历史后，回收不再被任何会话或草稿使用的图片。多标签页共用的图片会保留。
- 大图片请求的临时传输改用 IndexedDB，不再暂存到 `chrome.storage.local`。移除 `unlimitedStorage` 权限。
- 截图保留现有最长边 1600 像素的上限；超过 1.5MB 时继续等比例降低分辨率，保留完整已截取画面。缩小到最长边 1000 像素即停止，小图不额外处理。1.5MB 是目标值；仍保留单张 5MB、每批 6 张/30MB 的实际字节校验。
- 保留网页就地提问、400ms 尾沿防抖、Enter 提问、截图大小显示及转文字流程。

## 怎么用

选择网页元素后在网页输入问题，可保存多个标记，再在侧栏统一发送；也可直接点击网页小输入框中的「提问」。查看实际快照后发送，刷新侧栏和追问会沿用原截图。删除会话可同时清理不用的图片。

图片不再占用 `storage.local` 的 10MB 配额。会话文字、设置等仍共享这个 Chrome 配额；写入失败会提示，原有数据保留，可先导出并清理较早会话。IndexedDB 仍受浏览器正常磁盘配额管理。

## 验证

- TypeScript 检查、快速测试、共享顺序测试、React 组件测试、Chrome 构建/打包。
- 原生 Chromium IndexedDB 验证旧数据迁移、Blob 预览、刷新、跨标签读取、追问 payload、导出导入、共享图片删除清理，以及等比例缩图尺寸和字节数。
- 网页点选、遮盖敏感输入、标记、双向 hover、就地提问防抖和退出清理回归。
- Chrome 扩展完整 E2E 由 GitHub CI 验证，包括 60MB 历史图片从 IndexedDB 恢复为模型 payload。所有模型端点均为 mock，不读取或使用用户密钥。
