# 测试维护说明

## 维护原则

- 一个用例只保护一个可观察的业务边界；组合纯函数不能冒充端到端测试。
- 同类输入优先使用表驱动，异常分支和跨模块契约保持独立用例。
- 异步测试等待真实回调或受控 Promise，禁止用固定毫秒数猜测完成时间。
- 修改 `browser`、`chrome`、`window`、`document`、`navigator` 或计时器后，必须恢复进入测试前的全局属性。
- 通用存储和全局恢复使用 `tests/helpers/testEnvironment.js`，场景特有行为通过局部覆盖表达。
- 安全边界不能因精简而合并掉，包括 XSS、密钥脱敏、危险 URL、权限失败和请求竞态。

## 验证命令

```bash
bun test
bun test --randomize
bun test --randomize --no-isolate
bun run compile
```

## 仍需浏览器回归覆盖

当前单元测试使用轻量 DOM 和 Browser API Mock，尚不能证明以下真实浏览器行为：

- Chrome 与 Firefox 中扩展消息通道、Service Worker 唤醒和 Side Panel 生命周期。
- 页面真实 Selection、Shadow DOM、跨节点选区及 `contenteditable` 嵌套行为。
- Clipboard 权限拒绝、`execCommand` 兜底和复制成功态的真实计时显示。
- `chrome://`、商店页、跨域 iframe 和站点注入权限下的正文提取。
- 扩展安装、升级、刷新后的 storage.sync/local 数据迁移与配额限制。

## 单测维护与本轮修复结果

- 优化阶段将测试文件由 19 个精简为 17 个、用例由 247 个精简为 205 个；本轮只新增必要业务回归，不恢复未接入业务的辅助函数专属测试。
- 生词本消息协议和设置监听中的 9 处 `20ms` 固定等待已移除，改为等待真实回调或受控 Promise。
- 重复协议、测试内切片自证及未接入入口的 helper 专属测试已清理；内存存储 Mock 增加深拷贝隔离回归，真实安全、竞态、存储降级和后台多模态边界继续保留。
- 四项业务修复及集成补修新增 2 个聚焦测试文件和 14 个回归用例，当前共 19 个测试文件、219 个用例。
- `bun test --randomize --no-isolate` 为 219/219 通过；最终随机种子为 `1361679721`。
- 生词本自动复用及最终生命周期修复新增 1 个聚焦测试文件和 13 个回归用例；当前完整测试集共 23 个文件、275 个用例。
- 长文断点恢复新增 1 个存储协调器测试文件，并扩充状态与备份回归；当前完整测试集共 24 个文件、285 个用例，`bun test --randomize --no-isolate` 以种子 `2184822685` 全部通过。覆盖真实本地存储往返、pending 恢复、hydrate 门禁、正文身份校验、生产首写快照、串行检查点、删除胜出、容量边界、失败提示抑制和备份恢复清空断点。
- 网页全文总览新增 1 个纯函数测试文件并扩充导出回归；当前完整测试集共 25 个文件、293 个用例。覆盖完整分段证明、同 URL 多次阅读隔离、坏备份字段防御、48,000 字符硬边界、专用两消息载荷、fingerprint 失效和无自动请求副作用。

## 本轮已修复的业务问题

以下修复已由生产辅助函数和受控异步响应回归覆盖，真实浏览器边界仍见下方说明。

1. **历史图片在后续请求中继续保留**
   - 普通发送、网页续读、编辑和重试统一使用 `buildHistoryPayload`；当前图片直接进入当前用户消息，不再通过顶层字段重复注入。
   - 回归同时验证历史图片、当前图片各出现一次，已有 system 消息不会重复添加。

2. **网页通读消息保存有界可重放正文**
   - 每张首段或续段卡片最多保存 `16000` 字符的 `sourceContent`，并保存段序号与总段数；`excerpt` 继续只表示摘要。
   - 编辑指令与网页原文分开保存。编辑、重试先验证原文，旧记录缺失时提示重新通读，且不会先截断会话历史。

3. **续读只在有效业务成功后推进**
   - `success: false`、请求拒绝、取消和空结果都保留当前段；失败卡片可直接重试，重试成功后才推进，末段成功后才清理进度。
   - 进度提交绑定 requestId，迟到的旧响应无法覆盖新请求状态；初次长文首段失败也不会开放第二段入口。
   - done 先到时 pending 门禁继续阻止重复发送；停止和删除按显式请求归属处理原会话，较早网页段重放会回退到对应段并绑定新的助手卡片。

4. **Authorization 使用已解析的 API Key**
   - 显式传入 `params.apiKey` 时使用覆盖值，未传入时回退配置值；测试通过受控流式响应读取实际请求头，并在结束后恢复 fetch 和所有方法 Mock。

5. **生词本精确复用与安全回退**
   - 验证 Popup、网页浮窗和侧栏首轮纯文本共用 `TranslationService` 的本地精确匹配。
   - 验证图片、选区上下文、多轮消息与显式重新生成不会命中本地结果。
   - 验证存储读取超时后走正常模型流程，查找期间取消不再发模型请求，交付失败也不会二次请求。
   - 验证来源通过独立元信息交付，重新生成会清空旧来源；三个界面的来源标识均位于可复制正文之外。

6. **长文断点恢复**
   - 会话与版本化独立进度键联合 hydrate，恢复前不消费待办、不写初始空进度。
   - pending 不持久化；重开后保留部分结果并改为可重试错误，当前段不推进。
   - 完成态 sessions 与进度推进或末段删除通过同一次串行 `storage.local.set` 提交。
   - 断点按 `readingRunId`、页面信息、分段原文和助手消息交叉校验，坏数据与孤儿记录安全丢弃。

7. **网页全文总览**
   - 只在同一 `readingRunId` 的 `1..N` 段均有原文且紧邻成功非空回答时，于末段显示用户主动生成入口。
   - 模型输入固定为专用 system 与一条按段排序的 user 消息，只包含全部分段解读结果；最终字符串合计超过 48,000 字符时直接阻止，不截断、不遗漏分段。
   - 总览重试重新证明完整性并核对分段内容与助手 ID 的 fingerprint；旧结果失效时拒绝重试，流式期间跳过全文扫描。
   - 总览命令和结果随会话保存；停止、错误、恢复、复制和导出复用现有链路，不保存或导出内部大 Prompt。

## 多模态测试边界说明

当前多模态回归直接调用 `App.tsx` 已接入的 `buildHistoryPayload`，再进入后台 `buildMessagesPayload`，保护侧边栏与后台之间的图片和 system 载荷契约。它仍属于单元级生产链路验证，不等同于真实浏览器扩展消息通道验证。

网页长文完整正文只保留在当前侧边栏进度内存中；每张消息仅持久化当前段的最多 `16000` 字符。侧边栏关闭或扩展重载后，已保存段仍可编辑和重试，尚未生成的后续全文续读进度不会恢复。
